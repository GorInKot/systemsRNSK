# Заявки на доступы к системам

Вкладка корпоративного портала, через которую сотрудник один раз заполняет анкету и в один
клик формирует настоящие заявки (docx/xlsx) на доступы к корпоративным системам: учётная
запись, почтовый ящик, ПКЗИ, VipNet, КСЭД, ВКД, терминальный сервер, лаборатория ИИ.
Администратор ведёт реестр анкет сотрудников (импорт/экспорт, добавление вручную) и видит
журнал сформированных заявок.

Система заменяет прежний прототип — однофайловый `index.html` с данными в `localStorage`
браузера и обменом через экспорт/импорт JSON-файлов вручную (логика прототипа и то, откуда
взяты правила заполнения бланков, описаны в [LOGIC.md](LOGIC.md)).

Часть заявок (ЦУС, SIM-карта, удержание за перелимит связи, 1С:ПБиОТ) со временем нужно
перенести в основной портал — что для этого требуется и как устроена подстановка данных
в бланки, описано в [PORTING.md](PORTING.md).

| Часть | Технологии |
|---|---|
| `backend/` | Python 3.13, FastAPI, SQLAlchemy 2, Alembic |
| `frontend/` | React 19, TypeScript, React Router 7, TanStack Query, Vite |
| База данных | PostgreSQL 16 |
| Публикация | Docker Compose: `db`, `backend`, `frontend` (nginx раздаёт интерфейс и проксирует API) |

Собрана по тому же паттерну, что и соседний модуль портала «Заявки на автоматизацию»
(`zayavki_it`): тот же способ определения пользователя (`AUTH_MODE`), тот же `APP_BASE_PATH`
для встраивания вкладки, та же раскладка Docker Compose.

---

## Быстрый старт с демо-данными

Нужен только Docker.

```bash
docker compose up -d --build
docker compose exec backend python -m app.seed
```

Откройте http://127.0.0.1:8081. Без файла `.env` система работает в режиме разработки:
пользователь выбирается в правом верхнем углу. Администратор — «Орлова Анна Владимировна»,
остальные — сотрудники со своей анкетой.

Пересоздать демо-набор: `docker compose exec backend python -m app.seed --reset` (удаляет все анкеты).

## Подключение к порталу

Своего входа у системы нет — пользователь уже вошёл в портал через Active Directory. Портал
должен сообщать системе, кто пользователь: заголовками обратного прокси (`AUTH_MODE=headers`)
или подписанным JWT (`AUTH_MODE=jwt`). Подробности — в `.env.example` и в `backend/app/auth.py`
(режимы идентичны модулю `zayavki_it`, включая проверку `TRUSTED_PROXIES` и разбор групп AD).

`APP_BASE_PATH` — путь, по которому портал открывает вкладку (задаётся при сборке frontend,
после изменения нужна пересборка). `PORTAL_ORIGINS` — адреса портала для
`Content-Security-Policy: frame-ancestors`.

## Роли

| | Сотрудник | Администратор |
|---|---|---|
| Заполнять свою анкету, формировать заявки | ✓ | ✓ |
| Реестр анкет всех сотрудников, импорт/экспорт, добавление вручную | — | ✓ |
| Журнал сформированных заявок (аудит) | — | ✓ |

Администратором становится член групп из `ADMIN_GROUPS`. Роль пересчитывается при каждом входе.

## Шаблоны заявок

Реальные бланки (`types/*.xlsx`, `types/*.docx`) токенизируются сборкой `build/build.py`
(заполняемые ячейки/абзацы заменяются на метки `{{TOKEN}}`) в `build/tokenized/`. Backend
использует уже готовые токенизированные файлы из `backend/app/data/templates/` — при смене
исходных бланков в `types/` нужно:

```bash
python3 build/build.py            # нужны python-docx и openpyxl — только для сборки
./build/sync_templates.sh         # копирует build/tokenized/* в backend/app/data/templates/
```

Подстановку меток `{{TOKEN}}` на сервере делает `backend/app/services/templates.py` —
обычный `zipfile`, без ограничений браузерного движка прототипа (см. LOGIC.md).

## Резервное копирование

Данные хранятся в томе Docker `pgdata`.

```bash
docker compose exec -T db pg_dump -U dostup -Fc dostup > dostup-$(date +%F).dump
```

## Разработка

### Backend

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
docker compose up -d db                   # из корня проекта
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed
.venv/bin/uvicorn app.main:app --reload   # http://127.0.0.1:8000/api/docs
```

Новая миграция после изменения `app/models.py`: `.venv/bin/alembic revision --autogenerate -m "описание"`.

### Frontend

```bash
cd frontend
npm install
npm run dev        # http://127.0.0.1:5173, запросы /api проксируются на :8000
npm run build      # проверка типов и сборка
```

### Тесты

Backend — pytest на настоящем PostgreSQL (доменные правила, заполнение шаблонов, API, права
доступа). Нужна отдельная база `dostup_test`, при каждом запуске она пересоздаётся с нуля.

```bash
docker compose exec db createdb -U dostup dostup_test   # один раз
cd backend && .venv/bin/python -m pytest
```

## Что не реализовано в этом заходе

- Оптимистичная блокировка версий анкеты (последняя запись побеждает при одновременном
  редактировании сотрудником и администратором) — для self-service формы это приемлемый
  компромисс на старте.
- E2E-тесты фронтенда (Playwright) — покрыт только backend.
- SAP и 1С — заглушки («Шаблон в подготовке»), как и в прежнем прототипе: исходных бланков пока нет.
