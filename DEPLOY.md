# Деплой на сервер

Пошаговая инструкция для переноса системы на Ubuntu-сервер, на котором уже работает портал и
другие сервисы (в том числе соседний модуль `zayavki_it`). Общее описание — в
[README.md](README.md#установка-на-сервер).

## 0. Вопросы к команде портала (до начала)

1. Как портал передаёт личность пользователя: заголовками от обратного прокси или подписанным JWT.
2. Для заголовков — их имена, IP-адрес(а) прокси портала, кодировка кириллицы.
3. Для JWT — адрес JWKS или открытый ключ, `iss`, `aud`, где лежит токен, названия claim'ов.
4. Какая группа AD даёт права администратора этой системы (реестр сотрудников, журнал заявок).
5. Путь, по которому портал откроет вкладку (`APP_BASE_PATH`), и домен(ы) портала для `PORTAL_ORIGINS`.

Если эти ответы уже даны для `zayavki_it` тем же способом (headers/jwt) — годятся те же значения,
кроме `APP_BASE_PATH` (должен быть другим) и `ADMIN_GROUPS` (обычно отдельная группа).

## 1. Проверка сервера

```bash
docker --version || curl -fsSL https://get.docker.com | sh
```

Порт и подсеть по умолчанию — `8081` и `172.29.0.0/24`. Если на сервере уже развёрнут
`zayavki_it` (порт `8080`, подсеть `172.28.0.0/24`), конфликта не будет — подсети разные.
Если разворачивается что-то ещё третье, проверьте занятость и при конфликте измените
`HTTP_PORT` в `.env` и/или `subnet` в `docker-compose.yml`.

## 2. Перенос кода

```bash
sudo mkdir -p /opt/dostup && sudo chown $USER /opt/dostup
git clone <адрес-репозитория> /opt/dostup
cd /opt/dostup
```

## 3. Конфигурация `.env`

```bash
cp .env.example .env
```

Обязательно заполнить: `POSTGRES_PASSWORD`, `APP_BASE_PATH`, `PORTAL_ORIGINS`, `AUTH_MODE` и
соответствующие `HEADER_*`/`TRUSTED_PROXIES` или `JWT_*`, `ADMIN_GROUPS`. `ENVIRONMENT=production`
по умолчанию — блокирует `AUTH_MODE=dev` и отключает документацию API.

## 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f backend   # миграции применяются автоматически при старте
```

Демо-данные (`python -m app.seed`) в проде **не запускать**.

## 5. Публикация через прокси портала

Порт по умолчанию забинден только на `127.0.0.1:${HTTP_PORT}`. Прокси портала должен
проксировать `APP_BASE_PATH` на `http://127.0.0.1:${HTTP_PORT}`:

```nginx
location /access/ {
    proxy_pass http://127.0.0.1:8081/;
    proxy_set_header X-Remote-User    $remote_user_from_ad;
    proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Если сервер отдельный от портала — `HTTP_BIND=0.0.0.0` и обязательно закройте порт файрволом
для всех, кроме адреса прокси портала (`TRUSTED_PROXIES` в `.env` должен содержать этот же IP).

## 6. Проверка после запуска

- [ ] Вкладка открывается через портал по `APP_BASE_PATH`, а не напрямую по IP.
- [ ] Вход под реальным сотрудником проходит, ФИО и подразделение подхватились верно, анкета создаётся пустой.
- [ ] Сотрудник из `ADMIN_GROUPS` видит «Сотрудники» и «Журнал заявок», остальные — только «Анкету» и «Заявки».
- [ ] Заявка формируется и скачивается, открывается в Word/Excel без ошибок.
- [ ] `docker compose logs backend` не показывает ошибок авторизации (`401`, «Запрос пришёл в обход портала»).

## 7. Резервное копирование

```bash
docker compose exec -T db pg_dump -U dostup -Fc dostup > /backup/dostup-$(date +%F).dump
```

## 8. Обновление версии

```bash
cd /opt/dostup && git pull
docker compose up -d --build   # миграции применятся автоматически
```

Перед обновлением с изменением моделей БД — сделайте backup по п. 7. Если поменялись бланки в
`types/` — не забудьте `python3 build/build.py && ./build/sync_templates.sh` перед коммитом.

## Диагностика частых проблем

| Симптом | Причина | Что проверить |
|---|---|---|
| `401 Запрос пришёл в обход портала` | Заголовки пришли не от адреса из `TRUSTED_PROXIES` | Реальный IP прокси портала в логах nginx vs значение в `.env` |
| Вкладка не встраивается во фрейм | `PORTAL_ORIGINS` не совпадает с доменом портала | Заголовок `Content-Security-Policy` в ответе frontend |
| «Шаблон … не найден на сервере» | Файл шаблона отсутствует в `backend/app/data/templates` | `./build/sync_templates.sh` выполнялся и коммитился |
